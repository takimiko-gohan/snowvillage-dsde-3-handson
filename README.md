# 需要予測ハンズオン（東京23区 × SNOW BAKERY）

架空のカフェ・ベーカリーチェーン「SNOW BAKERY」の店ごとの毎日の売上を、Snowflakeで予測します。

- **ハンズオン①**（`01_forecast_ml_functions.ipynb`）：ML関数 `FORECAST`を使って店ごとの売上を予測する
- **ハンズオン②**（`02_global_model_ds.ipynb`）：Snowflake MLを使ってより高度なML環境を構築する
---

## 参加者の方へ：事前準備（約5分）

ハンズオン当日までに、次の **ステップ1〜3** を済ませてください。

### 必要なもの
- Snowflake アカウント（**トライアルアカウントで大丈夫です**。https://signup.snowflake.com/ から作れます）
- ACCOUNTADMIN ロールを使えるユーザー（トライアルで作ったユーザーなら使えます）

### ステップ1：データを作る（ワークシートで1回実行するだけ）
1. Snowsight にログインし、左のメニューから **Projects » Workspaces** を開く
2. **＋ Add new » SQL File** で新しい SQL ファイルを作る
3. [`setup/setup.sql`](setup/setup.sql) の中身を**すべて**コピーして貼り付ける
4. 右上の **▶ の横の ▼ » Run All**（すべて実行）をクリックする（Mac は ⌘+Shift+Enter、Windows は Ctrl+Shift+Enter）
5. 2〜3分待つ。**最後の結果が 0 行**なら準備完了です

このスクリプトがすること：
| 順番 | 内容 |
|---|---|
| 1 | GitHub の公開リポジトリにつなぐ設定を作る（`DSDE3_GIT_API`。ここだけ ACCOUNTADMIN を使います） |
| 2 | データベース `DF_HANDSON` を作り、このリポジトリを Snowflake に取り込む |
| 3 | `sql/` の SQL を順に実行して、駅・人口などの公開データ、合成した売上データ、学習用のビューを作る |
| 4 | データのチェック結果を表示する（エラーが 0 行なら OK） |

### ステップ2：ノートブックを Workspace に入れる
GitHub のこのリポジトリから、`01_forecast_ml_functions.ipynb` と `02_global_model_ds.ipynb` をダウンロードします。Workspace の **＋ Add new » Upload Files** でアップロードしてください。

### ステップ3：ノートブックがデータを読めるか確かめる
1. `01_forecast_ml_functions.ipynb` を開く
2. 右上の **Connect** から、ノートブックのサービス（Container Runtime）に接続する（初回は数分かかります）
3. 上から **「ロールを切り替え」「ウェアハウスを指定」「データ準備」** の3つのセルを実行する
4. 「**データは準備できています**」と表示されれば完了です。ハンズオン当日は、この続きから始めます

## 1. 題材

| 項目 | 内容 |
|---|---|
| 舞台 | 東京23区にある架空のカフェ・ベーカリーチェーン「SNOW BAKERY」（約100店＋10月開業予定の2店） |
| 予測対象 | 店舗 × 日の売上 |
| 業態 | 駅ナカ（乗降客数の上位駅）／駅前（駅から 80〜250m）／住宅街（駅から 600m 以上・人口の多いメッシュ） |
| 期間 | 売上 2024-10-01〜2026-09-30（2年）、カレンダー・天気・販促は 2026-10-31 まで |
| ①（初学者） | `FORECAST`（12店 × 日次、外生変数つき）と特徴量の重要度 |
| ②（DS） | XGBoost のグローバルモデル（全店を1モデル）。ホライズンを考えたラグ、期間をずらしたバックテスト、**Experiment Tracking で特徴量追加の効果を比較**、FORECAST との比較、新店・開業予定店の予測、SHAP、Model Registry → SQL 推論 |

### 実データと合成データの区別

| 種類 | データ | 出典 |
|---|---|---|
| 実データ | 駅の位置・乗降客数、500m メッシュ人口（2020年）、23区の境界、鉄道路線 | 国土交通省「国土数値情報」（S12 / N02 / N03 / 500mメッシュ別将来推計人口） |
| 実データ | 祝日 | 内閣府（`11_ref_holiday.sql`。公開前に内閣府の CSV と突き合わせる） |
| 合成 | 店舗・日次売上・販促 | `20_src_synth.sql`。店の位置と売上の大きさは上の実データ（乗降客数・人口）から決める |
| 合成（当面） | 天気（東京） | 気象庁の過去データに差し替える前提（気象庁は国交省の外局） |

## 消す. 合成データに仕込んだ構造（講師用。受講者には結果を見てから明かす）

| 要因 | 内容 |
|---|---|
| 基準客数 | 駅の人の流れ（最寄り駅の乗降客数の log）と周辺住民（750m 圏の人口の log）を、業態ごとの重みで足し合わせる |
| 曜日 | 通勤客中心の店（駅ナカ）は平日に強く、住宅街の店は週末に強い（通勤客の比率で連続的に変わる） |
| 年末年始・お盆 | 通勤客中心の店ほど落ち込む。元日は路面店が休業（売上 0） |
| 季節 | 12月 1.08倍、クリスマスイブ 1.35倍・当日 1.2倍、1〜2月 0.95倍、8月 0.96倍 |
| 天気 | 雨の日は住宅街・駅前の客が減り（最大 -25% / -18%）、駅ナカは少し増える（最大 +5%）。猛暑・厳寒で路面店は少し減る |
| 販促 | 毎月第2金曜からの3日間＋ランダムな約3%の日。客数 1.15倍、客単価 0.97倍 |
| 新店 | 開業1週間は 1.6倍、その後 0.75倍から約4か月で定常に戻る。15店が期間中に開業、2店が 2026年10月に開業予定 |
| 成長 | チェーン全体で年 +4%、店ごとに ±3% |
| ばらつき | 店 × 日のノイズ 約7%＋全店共通の日ごとの揺れ 約3%＋店の実力差（観測できない） |
| **イベント** | **2026-08-25（火）台風の接近**：降水 120mm、駅ナカ 0.6倍・駅前 0.35倍・住宅街 0.3倍。前日は 1.05倍（異常検知は扱わなくなったが、バックテストの難しい月として効く） |
